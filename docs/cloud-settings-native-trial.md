## 与本机设置的一致性

目标是以当前本机设置为基准：同一功能复用同一原生展示组件、分组、文案及保存/恢复默认交互。
**当前尚未达成完整一致**：部分只复用了外层卡片与基础控件，内部顺序、状态与功能仍有差异。
菜单顺序直接取本机 `TAB_IDS` 的受支持子集。云端目标标识常驻；取值、候选项、默认值和
写入始终来自选中的云实例，不能以本机 profile 或模型目录填充远端配置。

2026-10-29 本轮对齐：

- 通用新增云端显示语言和发送快捷键；Linux 目标显示 `Ctrl+Enter`，不采用控制端 Mac 的按键名称。
- 个性化新增链接打开方式、输入推荐和提问导航条，复用本机组件。链接的两行各自恢复默认，
  不清空 `desktopChat` 中其他覆盖项。云端显示语言只影响云桌面，不改变控制端语言。
- 智能通讯录与设备同步分别判断可用性，同步不可用不再隐藏通讯录开关；终端保留不可用的
  已选 Shell 提示，候选仍来自云端探测，不用本机已安装 Shell 代替。
- 移除已退出本机设置页、且不再影响新模型压缩策略的 Claude/Pi 全局压缩阈值。
  不删除云端旧配置文件，不把过时阈值当作模型级配置。
- 搜索按实际功能和能力过滤；能力撤回后丢弃该域的缓存展示，打开页面或切换分类不写入配置。

继续沿用现有 `settingsWeb` 的 `desktopGeneral` / `desktopChat` 字段及修订号、操作回执、
账号与目标校验，没有新增服务端接口或改变 wire 字段语义。仅在远端声明该能力且返回有效状态
时显示控件。没有能力的旧 runtime 保持原行为，本轮不需要 CIS 或云镜像部署。

以下差异必须区分原因，不能统称为“云端不支持”：

| 差异 | 当前边界 |
| --- | --- |
| 退出登录、增加/切换云端账号、云端应用内自更新 | 托管实例策略禁止；更新由 CIS 管理，普通本机客户端仍保留原功能 |
| 本机麦克风、系统权限、Agent Island 等 | 取决于目标平台和运行环境，不能把控制端硬件设置呈现为云端设置 |
| 用户提示词正文、Git 三档模式 | 现有远端读协议分别只返回定制状态、旧布尔值；不能猜测正文/模式。试用演示不代表真实接入 |
| 子代理/辅助模型/视觉桥接、模型级压缩、外观等其余原生配置 | 属于待对齐的原生远端适配，不代表云端没有能力。模型目录必须来自目标实例；不以旧全局压缩开关替代模型设置 |
| 通讯录管理/立即同步、工作目录级工具等操作 | 当前原生云面板没有完整操作接入；不显示会调用本机接口的假入口 |

验证使用真实原生组件和 Main 桥接的内存 CIS fixture：按字段写入/清除、非法值拒绝、
账号切换失效、缺失能力、未知 Shell 和本机 IPC 禁用均有回归。页面场景见
`apps/desktop/scripts/fixtures/cloud-settings/`，覆盖深浅色、多语言、窄窗口与下拉展开。
2026-10-29 定向回归共 375 项通过；Desktop 类型检查通过。页面矩阵为 4 个场景 ×

### Dev 签名与钥匙串

此前 Dev 使用 ad-hoc 签名，designated requirement 绑定本次二进制的 `cdhash`，重包后会变化。
固定 bundle ID 和 userData 并不足以保持钥匙串授权。macOS 钥匙串按签名要求追踪应用身份，
见 [Apple TN2206](https://developer.apple.com/library/archive/technotes/tn2206/_index.html)。

持续使用的 Cloud Dev 应复用同一个签名证书，保持独立 bundle ID、profile 和 safeStorage 名称。
本机已使用独立 Dev 自签身份重新签署 `.2`，没有修改 ASAR 或登录数据、没有调整全局证书信任。
这仍不是 Developer ID 公证发行包；分享正式测试包时应使用团队批准的签名与公证流程。
签名工具仅接受隔离 Dev 的暂存副本，缺少固定证书时失败，不回退临时签名：

```sh
node apps/desktop/scripts/ci/sign-cloud-dev-local.mjs \
  --app /path/to/staging/Cindy\ Cloud\ Dev\ CN.app \
  --keychain /path/to/dev-signing.keychain-db \
  --identity <persistent-certificate-SHA1>
```

证书只初始化一次，私钥和钥匙串密码放仓库外私有存储；后续沿用，不随构建生成。工具不改
凭据条目 ACL，不更换服务名，不把凭据降级成明文，也不签运行中的 `/Applications` 应用。
旧 ad-hoc 身份切换到固定身份时仍需系统授权一次；“允许”通常仅本次，“始终允许”才持久记住。

隔离原生钥匙串测试禁止弹窗，确认不同二进制使用同一证书可以读取上一构建创建的合成条目；
相同 identifier 换成 ad-hoc 签名读取被拒绝。随后从干净源码重新打包 `.3`，沿用同一证书安装，
实际启动读取原 Dev 凭据并进入主界面，本次未再要求用户处理钥匙串提示。这是一次真实跨重包
结果，不代表系统会在任何凭据或授权状态下永久免提示。

补齐 fresh Forge 产物的签名处理：仅修改 Info.plist 仍可能留下 `com.github.Electron` 签名
identifier。签名工具现在显式按主应用及各 Helper 的隔离 bundle ID 签署，再执行深度严格校验，
不能只保留旧 identifier。新产物的 designated requirement 已核对为隔离身份与固定证书。

## 接入路径与身份

`设置 → 云实例` 显示当前账号的实例清单，选择实例后进入有明确云端目标标识的原生设置。
复用客户端设置侧栏、搜索、主题、表单和保存组件，覆盖简中、繁中、英语、日语、韩语。
本机设置与云端设置分别取值。共享模型选择器会订阅本机缓存，但以目标 deviceId 读取远端目录；云端设置写入不调用本机配置保存接口。

```text
原生设置页面 → preload 封闭方法 → Main 身份/窗口/目标校验
  → CIS 普通客户端入口 → 原有 settingsWeb 队列 → Host settingsManagement
```

Main 持有 Access Token、配置的 HTTPS 服务地址和远程会话 ID。Renderer 只取得本机句柄，
不能覆盖账号、企业、服务地址、控制设备或实例身份。句柄绑定自有顶层 frame；窗口销毁、
导航、账号/区域/设备变化时失效，异步响应前后复核作用域。Token 轮换不等于身份变化。
HTTP 禁止 Cookie、重定向与 referrer，并限制超时和响应体大小。

CIS 通过 `@cindy/auth-verify` 校验普通用户 Bearer，逐请求核对实例归属、企业准入、控制设备、
会话和 runtimeId。该入口不接受 Platform 身份；原网页 Cookie/Origin 和 Host 身份入口不变。
原生准入可以按实例或通过 `settingsWeb.nativeClientAllInstances` 开启；它不扩大账号权限。

客户端云实例入口只对通过 CIS 准入的账号显示。只有云模式、已登录、登录初始化完成且
Main 身份已提交后，才调用 `GET /client/access`；严格校验
`{ schemaVersion: 1, allowed: boolean }`。此接口不读取实例列表；有权限但尚未领取实例
仍返回 true。设置分类、搜索、侧边栏快捷设置和设置深链共用结果，未确定、拒绝或失败时隐藏。

前台每分钟以及重新聚焦、恢复网络时复核，有效结果后的 5 秒内合并重复触发。
退出/换账号立即丢弃旧结果，Main 和 Renderer 都拦截旧身份的迟到响应；权限不落盘，
不根据组织名称、已登录状态或设备 ID 猜测。查询不会领取、唤醒或创建设置会话。
每次实际操作仍由 CIS 重新校验管理/租户/邀请准入和实例归属，查询成功不授予后续操作权。
这只控制云实例管理入口，不改变普通设备互联权限。

先部署包含新接口的 CIS，再交付客户端。旧 CIS 返回 404、鉴权失败或网络错误时，
新客户端隐藏云入口，保留其他功能；不回退到实例列表或本地推断。旧客户端的既有接口
仍受服务端逐请求准入约束。此改动不需要数据库迁移或新增配置。

## 源码客户端的本地联调

使用仓库的 Desktop 启动包装，显式选择区域、独立沙箱和被动模式：

```sh
pnpm restart:desktop:remote --region=cn --isolated=dev --passive
pnpm desktop:whoami --all
```

以 `DESKTOP_DEV_VERDICT=ready` 和 `desktop:whoami` 的 checkout、区域、沙箱结果为准。
首次在独立沙箱登录，不复制正式版或隔离发行包的凭证和数据。登录后访问的仍是真实云实例。

CN 源码 remote 模式默认读取 `config/endpoint.json`。云联调须准备一份仓库外的完整
端点清单，包含当前区域的 `region` 和 HTTPS `cloudInstanceApiBaseUrl`（服务根地址，
例如 `https://cis.example.com`），显式传入每次启动：

```sh
pnpm restart:desktop:remote --region=cn --isolated=dev --passive --endpoints-file=/absolute/path/to/private/endpoint.json
```

`--endpoints-file` 随启动包装传到实际进程，不接受继承的 `XDT_ENDPOINT_MANIFEST_FILE`

## 现有协议的复用

| 路由                                                   | 用途                          |
| ------------------------------------------------------ | ----------------------------- |
| `POST /client/instances/:instanceId/settings/sessions` | 创建短期设置上下文            |
| `POST .../sessions/:sessionId/heartbeat`               | 续租                          |
| `POST .../sessions/:sessionId/requests`                | 原有 SettingsWebCommand       |
| `GET .../sessions/:sessionId/requests/:requestId`      | 查询原请求，可沿用 resultWait |
| `GET .../sessions/:sessionId/authorizations`           | 恢复本会话发起的授权状态      |
| `DELETE .../sessions/:sessionId`                       | 撤销并回收本会话操作          |

客户端直接引用既有 `settingsWeb.ts` / `settingsManagement.ts` 业务 wire，不新增 Host
resource 或第二套配置执行器。读取按分类并沿用 `readBatch`/`remainingDomains`；缺少能力时
按旧协议降级。每个句柄最多 4 个在途请求。

保存使用原读 revision/operationId；并发冲突保留草稿。POST 响应丢失时查询原 requestId 或
receipt，不自动重发写入。成功后回读。CIS 分开网页、原生与清理队列的归属和容量；撤销只清理
该会话发起的授权，不能取消别人的操作或登出已有账号。

## 授权与回收

供应商、IM、MCP 沿用 `list/run/status/respond/cancel`、动作票据、资源锁和回执。
Main 拒绝跨窗口票据和操作 ID。离页、取消、关闭、过期均有回收路径，不能把“已收到回调”
显示成“账号已绑定”。

OpenAI 等 loopback 授权由 Main 先监听 Host 指定的本机回环地址、非特权端口和回调路径，
核对唯一 state 后沿原 respond 命令发送到同一云实例操作。PKCE、换票和持久化继续由云端 CLI
完成，不同步凭证。端口冲突不抢占；完成时等待本机 HTTP 结果页发完再释放监听，取消立即释放。
云端远程 Codex 登录只在该子进程设 `BROWSER=/bin/true`，避免额外打开无人管理的浏览器。
授权浏览器回收确认目标消失和进程退出，处理关闭与目标自行销毁的竞态。

## 实例领取、状态与维护

- 空列表提供显式“领取云实例”，复用既有无 ID wake 分支。已有实例唤醒始终带 ID；写前核对
  归属，响应不明只查询结果，不自动重放领取。
- `loginRequired` 打开客户端共享的 `LoginPageView`，保留短信、已启用的第三方方式、
  SSO 企业 ID 输入、多连接选择和后续验证。云端目标持续标明；短期 continuation 仅在
  Main 与 CIS 间传递，不进 Renderer、日志或磁盘，不复制本机凭证到云端。
- 概览独立于 Host 设置会话，休眠时仍可显示状态和唤醒。休眠确认具体目标与任务影响。
  可见页面转换状态每 5 秒、稳定状态每 30 秒读取，禁止同实例重复写入。
- 云版本、可用更新与本机版本分别显示。自动更新及维护时段显式保存，携带 revision 与
  defaultsRevision，保留任务保护策略。开启开关不等于立即升级。
- 版本信息旁的“立即升级”复用 CIS 所有者 `GET/POST /instances/:instanceId/maintenance/upgrade`，
  只提交请求 UUID，不允许客户端选择镜像或跳过备份。可在维护窗口外、自动更新关闭时申请；
  不修改自动更新选择和定时任务。CIS 等待任务保护检查通过后执行停机备份及升级。
- 直接消费实例清单中的 `maintenanceUpgrade`：保留完整上游/云修订/区域/架构版本，显示持久化
  队列、备份、升级、完成或恢复占用状态。已有活动操作、停机、资源变更和未保存的维护草稿期间
  禁止重复申请；响应不明时要求先刷新，不自动重放。旧 CIS 缺少能力字段时保留版本与停启功能，
  不展示主动升级按钮，不回退到绕过维护的升级接口。
- 新增 IPC 仅供当前登录账号的本机可信 Renderer，经 Main 访问 CIS，不加入 DeviceLink 通用
  invoke 白名单，也不通过 SSH 执行升级。该入口不依赖云端 Host 在线设置会话。
- 维护时区使用可搜索 IANA 选择器；维护方式字段固定宽度，菜单不因选项文字长短收缩。
  自定义时段支持每周日期、跨午夜和重叠校验，不提供修改定时任务的入口。

## 个人云身份登录桥接与云端账号保护（2026-10-26）

此前个人账号领取仅停在待初始化，是当次实现的限制；本轮按用户确认补上个人登录。
客户端不再要求个人实例有 orgSlug，仍只为当前身份已拥有且待登录的设备创建 CIS attempt。
跳转保持同源、固定路径和短期 capability 校验，并修正实际 24 字符 base64url attemptId
被当成 UUID 的问题。账号或窗口失效后清理旧 attempt；迟到创建响应仅供取消，不打开页面。
已取消/过期的流程允许明确重新发起，瞬时网络错误不重放创建。

CIS 手机号、邮箱、第三方登录和补绑全部复用现有 auth 协议；server 选择实例所属账号，
验签确认 membership、passport 和 device 后，只交付实例 resource refresh token。普通客户端
登录态不会复制到云端，个人账号没有自动获得云权限。须先交付 CIS，再使用此客户端。
原生客户端沿现有 Auth/CAPTCHA 链路发码，CIS 的新增 `personal/prepare-code` 只记录
待验证目标，实际验码、owner/device 检查和云凭证回写仍由 CIS 完成。云端挑战页取目标
Auth realm，不受本机登录方式改变。微信、Apple、SSO 直接打开对应 Auth authorize URL，
沿原 CIS capability 轮询；不再跳到 CIS 的登录方式选择页。浏览器入口继续使用可选托管
发码模式并检查 `captcha.requestCodePage`，与原生接入的依赖分开。
因此认证服务、CIS、原生客户端的交付状态必须分别记录，不把源码完成写成已部署。

云镜像额外应用 `deploy/linux-desktop/runtime-identity/`：隐藏设置资料卡的“退出登录”、
“登录更多账号”和侧栏账号切换。主进程沿用现有 `assertInstanceAuthMutationAllowed`，
这些操作即使直接调用也被拒绝；CIS bootstrap 和正常刷新继续可用。该覆盖对普通客户端
及本机 Dev 包不生效，也不屏蔽供应商/插件自身的授权或退出。

本地验证：原生云客户端 170 项回归通过；云身份覆盖在当前 checkout 和冻结云源码上均验证
实际资料卡渲染、主进程拦截及 CIS 自有令牌放行。CIS 独立 Chromium 覆盖五语、明暗主题、
320/390/1280px 共 30 组布局，模拟验证码的云设备回写、第三方补绑和取消通过。
这些认证响应是合成 fixture，不是手机号/邮箱、Google/Apple/微信的真实账号验收。
另以隔离浏览器覆盖认证服务托管发码：实际 challenge/cData 和 request-code 路由、
来源 IP 与一次性校验运行，外部 Turnstile/Siteverify 和短信/邮件发送采用测试替身。
没有重新授权或创建先前已删除的个人测试实例，也没有改动云实例运行状态。
